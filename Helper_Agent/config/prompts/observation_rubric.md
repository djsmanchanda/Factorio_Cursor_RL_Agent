# Observation rubric

1. Establish provenance and terminal class before interpreting symptoms.
2. Treat typed blockers as first-class evidence; do not override their recorded
   classification without a cited correction.
3. Distinguish repeated failure signatures from one-time operational issues.
4. Prefer missing observations over speculative causes.
5. Preserve successful workflows even when the run later fails.
6. Never interpret missing user feedback as confirmation or rejection.
7. Recommendations must name an improvement category, not an implementation.
