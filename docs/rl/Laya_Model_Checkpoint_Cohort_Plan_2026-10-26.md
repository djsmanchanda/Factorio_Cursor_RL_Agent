## Common experimental contract

For each matched comparison, freeze the same toolkit/mod/engine, source-save family, offered operations and state facts, starting inventory/research, objective, checkpoint predicates, exploration policy, game/idle/wall windows and hardware-resource policy. Scheduler arm order should be balanced/interleaved by seed so a model does not systematically receive different host contention or time of day. Candidate CPU/model-service contention must not starve only one arm. Do not edit/redeploy/restart under an active frozen campaign.

Record every planned job, including prepare failures, crashes, invalid model outputs, interruptions and deadline-not-started cases. Preserve the all-planned primary accounting and report completed matched-pair diagnostics separately. Pair policy seeds/starting snapshots, but do not call diverged same-seed trajectories matched-state counterfactuals. The retained C35–C38 scope has one save hash; seed replication on that map is policy-seed evaluation, not unseen-terrain generalization. Add new map families before making a map-generalization claim.

Default effectiveness endpoints are **strict C6-ever primary**, **strict fresh-final C6 secondary**, earlier strict C2/C3/C4/C5 service guardrails, tool/safety failures and full terminal accounting. Report science/research targets separately when exposed. Retained milestone flags, final conditions, production stock and actual consumption/service are distinct. Check target exposure and the unchanged stop contract before interpreting a cohort; C38's early decision-idle stops illustrate why an unexposed arm cannot supply a negative model result. Keep all such jobs in the ledger even if the experiment must be declared invalid.

Mechanism diagnostics include consumer-cell ownership/running state, prerequisite shortages, refused-operation repetition with unchanged facts, pending construction progress, useful waiting, earlier milestone exposure, action entropy and calibrated uncertainty. Mechanisms explain outcomes; they do not replace the primary endpoint or justify post-hoc reward changes. A geometry/tool defect is repaired and compared independently, with a new frozen version for all future arms.

Report paired completion counts and uncertainty, including discordant seeds, alongside target time, censored runs, wall/game time, inference cost and material/service outcomes. Predeclare primary contrasts and account for multi-arm/model selection. Development-stage metrics are exploratory; use E's untouched seeds only once the candidate is frozen. Do not repeatedly peek and change the stopping budget. A null or imprecise result can justify more evidence, not an unearned winner.

## Checkpoint and data discipline

- Each artifact identity includes base revision, initialization checkpoint, adapter and head hashes, dataset/split/renderer/target hashes, training seed, update count, examples/tokens seen, optimizer/recipe, precision, training code, calibration membership/hash and deploy runtime. A path named `latest` is not an identity.
- Save base, intermediate and final checkpoints at predeclared training budgets; shortlist offline using development data before spending whole Factorio cohorts. Use architecture-appropriate recipes with comparable declared data and tuning/compute budgets; equal learning rates or optimizer steps do not make different backbones equally trained.
- Fit calibration separately for each checkpoint using only the calibration partition. The causal treatment is the recorded checkpoint-plus-calibrator policy bundle; do not describe it as weights alone if calibration changes. Keep exploration fixed.
- Reuse the same qualified data release for the first cross-model adaptation. If later data, facts, rewards or renderer change, call it a new training generation and retain a clean contrast. Fresh development rollouts may enter a future training generation after closing their experiment; they never enter that generation's test split. Final confirmation seeds/trajectories remain excluded from training/calibration/model selection.
- Supervised adaptation of historical decisions precedes online RL. A later environment-reward cohort compares a frozen supervised checkpoint to its RL continuation under the same task contract; it cannot be called RL merely because a supervised trainer uses a proper-score reward. That stage is not yet launch-ready.
