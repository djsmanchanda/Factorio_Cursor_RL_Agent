# Owning GPT implementation campaign

The October 11, 2026 user instruction supersedes the earlier fresh-Haiku
implementer and GPT supervision roles for the new campaign. The persistent
OpenCode Go `opencode-go/deepseek-v4.1-flash/high` session remains observer and
planner. GPT-6.1-Sol/high implements in the existing owning T3/Codex session.
There are no scheduled GPT check-ins and no Haiku or Muse calls.

Use `tools.campaign_pingpong --agent-topology deepseek-codex`, with explicit
private ports, writable campaign worktree and exact model configuration.
`campaign.json` records the actual root T3 thread and Codex resume cursor.
The native Codex `turn_context` verifies model and effort; mismatches refuse
delivery. The installed T3 `thread.turn.start` RPC sends plans to that owning
thread, with durable command/message IDs and explicit model selection. A
restart resends the same command or waits for its existing completion; it does
not allocate another implementation agent or another episode.

Each request names the saved DeepSeek session, evidence, prior effect, plan,
verification obligations and absolute edit deadline. GPT writes an identity
checked completion packet at the named campaign path. The harness relays the
packet verbatim to the same DeepSeek session, obtains independent review,
proves focused regressions fail on the preceding revision and pass on the
candidate, runs the prescribed fast gate, and performs only scoped commits.
An accepted candidate is then frozen and stamped for a new disposable run on
the same campaign branch. No merge, push, adoption or production promotion.

The controller sets T0 on actual first entry and persists D=T0+6 wall hours
and W=T0+7 wall hours once. Restarts preserve both. No new run, implementation,
edit or commit starts at or after D. A run started before D may continue in
observation mode. The final five minutes before W are reserved for stopping
owned disposable processes, retaining partial evidence and publishing the
report regardless of research status. This is the explicitly authorized
campaign wrap, not an ordinary progressing-episode duration cap. Systemd has
no finite runtime kill limit.

A separate controller watchdog probes private-world productive counters
every ten seconds, even during blocking model/operation calls. It observes
relevant crafting/delivery, machines, ghost completion, funded construction,
loan counters and research advances. Durable high-water evidence prevents
stock oscillation and successful no-op retries from resetting the clock.
Thirty wall minutes without demonstrated progress requests a cooperative
stop (`stalled_wall_30m`); an operation that cannot finalize within one minute
is stopped as a forced partial run. Missing telemetry cannot prove a stall;
after thirty minutes of missing observations it is a separately named hard
failure. Both conditions retain evidence for DeepSeek's blocker diagnosis.

The runner publishes its useful-state signature in `latest-status.json`.
This campaign passes `--stall-observation-ticks 0`, disabling the earlier
18,000-tick guard. It sets no decision, total tick, proxy checkpoint or episode
wall budget. Completion requires the existing verified research contract for
`mining-productivity-4`, with requested and observed game speed recorded.

The report retains every allocated episode, including lifecycle crashes,
forced partial runs, transport failures, observations, candidate diffs,
proofs, gate logs, commit/run identities and session transcripts. A final
native message returns the report to the owning GPT thread for an audit;
that message authorizes reading and reporting, not another fix cycle.
